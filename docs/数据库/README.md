# 数据库专区

数据库是应用系统的核心组件，负责数据的存储、检索和管理。本目录涵盖MySQL、分库分表等核心数据库技术。

## 一、数据库概述

### 1.1 数据库分类

| 类型 | 特点 | 代表产品 |
|------|------|----------|
| **关系型数据库** | 结构化、事务性、SQL | MySQL、PostgreSQL、Oracle |
| **NoSQL数据库** | 非结构化、高可用、灵活 | Redis、MongoDB、Cassandra |
| **NewSQL数据库** | 分布式、强一致、弹性 | TiDB、CockroachDB |

### 1.2 数据库选型因素

| 因素 | 说明 |
|------|------|
| **数据结构** | 是否需要复杂关系 |
| **事务需求** | 是否需要ACID |
| **性能要求** | 读写吞吐量 |
| **扩展性** | 是否需要水平扩展 |
| **成本** | 许可费用、运维成本 |

## 二、MySQL 深入理解

### 2.1 核心概念

- **存储引擎**：InnoDB、MyISAM、Memory
- **索引**：B+树索引、哈希索引、全文索引
- **事务**：ACID特性、隔离级别
- **锁机制**：行锁、表锁、意向锁

### 2.2 架构组成

```
连接层 → 服务层 → 存储引擎层 → 文件系统
```

### 2.3 事务隔离级别

| 级别 | 说明 | 问题 |
|------|------|------|
| **READ UNCOMMITTED** | 读取未提交数据 | 脏读、不可重复读、幻读 |
| **READ COMMITTED** | 读取已提交数据 | 不可重复读、幻读 |
| **REPEATABLE READ** | 可重复读 | 幻读（InnoDB已解决） |
| **SERIALIZABLE** | 串行化 | 性能差 |

### 2.4 MVCC（多版本并发控制）

InnoDB通过MVCC实现高并发：

- **Read View**：快照读时构建的一致性视图
- **Undo Log**：记录数据的历史版本
- **版本链**：通过roll_pointer串联历史版本

## 三、分库分表

### 3.1 分库分表场景

当单表数据量达到千万级别时，需要考虑分库分表：

- **性能瓶颈**：索引过大、查询变慢
- **存储瓶颈**：单表过大影响备份恢复
- **运维困难**：DDL操作耗时过长

### 3.2 分库分表策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **水平拆分** | 按行拆分 | 用户数据、订单数据 |
| **垂直拆分** | 按列拆分 | 分离冷热数据 |
| **库内分表** | 同一库内拆分 | 中等数据量 |
| **跨库分表** | 跨多个库拆分 | 大数据量 |

### 3.3 分片键选择

| 类型 | 说明 | 注意事项 |
|------|------|----------|
| **用户ID** | 按用户分片 | 需考虑数据倾斜 |
| **时间范围** | 按时间分片 | 热点问题 |
| **地域** | 按地域分片 | 业务相关性 |

### 3.4 分库分表中间件

| 中间件 | 特点 |
|--------|------|
| **ShardingSphere** | 开源、功能完善 |
| **MyCAT** | 国产、活跃 |
| **Vitess** | 谷歌开源、云原生 |

## 四、数据库优化

### 4.1 SQL优化

- 使用合适的索引
- 避免SELECT *
- 合理使用JOIN
- 子查询优化

### 4.2 索引优化

| 类型 | 适用场景 |
|------|----------|
| **B+树索引** | 范围查询、排序 |
| **哈希索引** | 等值查询 |
| **复合索引** | 多条件查询 |
| **覆盖索引** | 查询列都在索引中 |

### 4.3 配置优化

- innodb_buffer_pool_size
- query_cache_size（MySQL 8.0已移除）
- max_connections
- innodb_log_file_size
