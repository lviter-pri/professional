# AI 行为准则

## 核心原则

AI 必须作为“辅助开发者”运行，严格遵守代码稳定性原则，严禁擅自变更系统契约。

## 禁止行为
- **禁止**：严禁修改任何已有接口（`RemoteService`、`Controller`）的方法签名、入参结构及出参定义。
- **禁止静默覆盖**：严禁在未备份或未确认的情况下覆盖已有业务逻辑代码。
## 允许行为
- **允许**：仅在 API 定义（Interface）和数据模型（Model/DTO）明确存在后，允许根据规范填充其内部逻辑实现。
- **代码优化**：允许在不改变外部调用的前提下，进行符合 Clean Code 原则的重构。
## 执行前必须遵守
- **涉及接口定义时**：检测到需要新增接口（RemoteService 接口文件）时，必须停止，需要先跟用户沟通确认。
- **基础架构生成 (CRUD)**
  - **场景**：检测到需要新增 `Model`、`Entity`、`Mapper`、`Service`、`Controller` 等整套基础组件。
  - **要求**：停止执行。告知用户："请提供标准 DDL 定义"。
  - **后续**：仅在用户提供 DDL 后，方可生成对应的映射类及基础 CRUD 代码。
## Spec 文档规范
- 需要用户手动完成的任务必须在 tasks.md 中使用 `[MANUAL]` 前缀标注
- AI 在实施阶段遇到 `[MANUAL]` 任务时，必须停止并等待用户完成
