# JVM

Java虚拟机（Java Virtual Machine，JVM）是Java平台的核心组件，负责将Java字节码转换为机器码并执行。深入理解JVM对于编写高性能Java应用和排查性能问题至关重要。

## 一、运行时数据区

JVM在执行Java程序时会将内存划分为几个不同的数据区域，每个区域有其特定的用途和生命周期：

### 1.1 程序计数器（Program Counter Register）

- 线程私有，每个线程都有独立的程序计数器
- 记录当前线程执行的字节码行号
- 唯一不会抛出OutOfMemoryError的区域

### 1.2 Java虚拟机栈（Java Virtual Machine Stack）

- 线程私有，存储局部变量表、操作数栈、动态链接、方法出口等
- 局部变量表存放编译期可知的基本数据类型和对象引用
- 栈深度由-Xss参数控制，过深会抛出StackOverflowError

### 1.3 本地方法栈（Native Method Stack）

- 为本地方法（Native Method）服务
- 与Java虚拟机栈类似，但针对native方法

### 1.4 Java堆（Java Heap）

- 所有线程共享，是GC的主要区域
- 存放对象实例和数组
- 可通过-Xms和-Xmx参数调整大小
- 分为新生代和老年代，新生代又分为Eden区和两个Survivor区

### 1.5 方法区（Method Area）

- 所有线程共享，存储类信息、常量、静态变量、即时编译后的代码
- 在JDK 8及以后，方法区被元空间（Metaspace）替代，使用本地内存

### 1.6 运行时常量池（Runtime Constant Pool）

- 方法区的一部分，存放编译期生成的常量和符号引用
- 包含字符串常量池，支持String.intern()方法

## 二、对象

### 2.1 对象创建过程

1. **类加载检查**：检查类是否已加载、解析和初始化
2. **分配内存**：从堆中为对象分配内存空间
3. **初始化零值**：将分配的内存空间初始化为零值
4. **设置对象头**：存储对象的哈希码、GC分代年龄、锁状态等信息
5. **执行init方法**：调用构造函数初始化对象

### 2.2 对象内存布局

- **对象头**：Mark Word + 类型指针 + 数组长度（仅数组对象）
- **实例数据**：对象的字段值
- **对齐填充**：保证对象大小为8字节的倍数

### 2.3 对象访问方式

- **句柄访问**：通过句柄池间接访问对象，稳定但多一次指针定位
- **直接指针访问**：直接存储对象地址，更快但对象移动时需更新引用

## 三、内存溢出/内存泄露

### 3.1 常见内存溢出类型

- **OutOfMemoryError: Java heap space**：堆内存不足
- **OutOfMemoryError: PermGen space / Metaspace**：方法区/元空间不足
- **StackOverflowError**：栈深度超过限制
- **OutOfMemoryError: unable to create new native thread**：无法创建新线程

### 3.2 内存泄露场景

- 静态集合持有对象引用
- 监听器未移除
- 缓存未设置过期策略
- 内部类持有外部类引用
- 连接资源未关闭

### 3.3 排查方法

- 使用jmap导出堆转储文件
- 使用MAT（Memory Analyzer Tool）分析
- 使用jstat监控GC状态
- 使用VisualVM进行实时监控

## 四、GC（垃圾收集）

### 4.1 垃圾判断算法

- **引用计数法**：简单但无法处理循环引用
- **可达性分析算法**：通过GC Roots遍历对象图，不可达对象标记为垃圾

### 4.2 常见垃圾收集器

| 收集器               | 新生代  | 老年代   | 特点          |
| ----------------- | ---- | ----- | ----------- |
| Serial            | 复制算法 | 标记-整理 | 单线程，适合小堆    |
| ParNew            | 复制算法 | -     | Serial的并行版本 |
| Parallel Scavenge | 复制算法 | 标记-整理 | 高吞吐量优先      |
| CMS               | -    | 标记-清除 | 低延迟优先，有碎片问题 |
| G1                | 分区收集 | 分区收集  | 兼顾吞吐量和延迟    |
| ZGC               | 分区收集 | 分区收集  | 超低延迟，大堆友好   |

### 4.3 GC调优策略

1. 选择合适的垃圾收集器
2. 合理设置堆大小（-Xms/-Xmx）
3. 调整新生代比例（-XX:NewRatio/-XX:SurvivorRatio）
4. 设置晋升阈值（-XX:MaxTenuringThreshold）
5. 监控GC日志，分析停顿时间和频率

## 五、类加载机制

### 5.1 类加载过程

1. **加载**：读取class文件到内存，生成Class对象
2. **验证**：确保class文件格式正确、符合JVM规范
3. **准备**：为类变量分配内存并初始化为零值
4. **解析**：将符号引用转换为直接引用
5. **初始化**：执行类构造器`<clinit>`方法

### 5.2 类加载器层次

- **Bootstrap ClassLoader**：加载核心类库（rt.jar等）
- **Extension ClassLoader**：加载扩展类库（ext目录）
- **Application ClassLoader**：加载应用类路径下的类
- **自定义类加载器**：按需加载特定类

### 5.3 双亲委派模型

- 类加载器收到加载请求时，先委托父类加载器加载
- 父类加载器无法加载时，才由子类加载器自己加载
- 保证Java核心类的安全，避免重复加载

### 5.4 破坏双亲委派的场景

- 热部署需求
- 模块化加载
- SPI机制（如JDBC驱动加载）
