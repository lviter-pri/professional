# Slf4j 日志规范

## 使用时机
- 需要在代码中添加日志时
- 不确定日志级别选择时
- 关注日志性能问题时
- 需要正确记录异常日志时
- 需要追踪请求链路时

---

## 快速开始

### 添加 @Slf4j 注解

在类上添加 `@Slf4j` 注解即可使用（需要 Lombok 依赖）：

```java
@Slf4j
@Service
public class XxxService {
    public void doSomething() {
        log.info("处理开始");
    }
}
```

### 手动声明 Logger

如果不使用 Lombok，可以手动声明：

```java
public class XxxService {
    private static final Logger log = LoggerFactory.getLogger(XxxService.class);
    
    public void doSomething() {
        log.info("处理开始");
    }
}
```

## 1. 日志格式规范

### 1.1 基本格式

推荐格式：`[类名.方法名] 操作描述: 关键参数`

```java
log.info("[AuthService.loginUser] 用户登录: userId={}", userId);
log.error("[KafkaConsumer.processMessage] 消息处理失败: topic={}, offset={}", topic, offset);
```

**格式要素：**
- **定位信息**：类名.方法名，便于快速定位代码位置
- **操作描述**：清晰描述正在执行的操作
- **关键参数**：记录影响业务的核心参数

### 1.2 占位符使用

使用占位符避免字符串拼接，提高性能：

```java
// 正确 ✅
log.info("处理订单: orderId={}, status={}", orderId, status);

// 错误 ❌ - 即使日志级别关闭也会执行字符串拼接
log.info("处理订单: orderId=" + orderId + ", status=" + status);
```

### 1.3 异常日志

异常作为最后一个参数，自动记录堆栈信息：

```java
try {
    processOrder(order);
} catch (Exception e) {
    // 正确 ✅ - 异常放在最后
    log.error("[OrderService.processOrder] 订单处理失败: orderId={}", orderId, e);
    
    // 错误 ❌ - 异常信息丢失
    log.error("[OrderService.processOrder] 订单处理失败: {}", e.getMessage());
}
```

### 1.4 日志格式模板

```java
// 方法入口
log.info("[{}.{}] 开始执行: param1={}, param2={}", 
    className, methodName, param1, param2);

// 方法出口
log.info("[{}.{}] 执行完成: result={},耗时={}ms", 
    className, methodName, result, duration);

// 异常处理
log.error("[{}.{}] 执行失败: param={}, error={}", 
    className, methodName, param, e.getMessage(), e);
```

## 2. 日志级别规范

### 2.1 级别选择指南

| 级别 | 使用场景 | 示例 | 生产环境建议 |
|------|---------|------|-------------|
| **TRACE** | 最详细的调试信息，方法进入/退出、变量变化 | `log.trace("进入方法: {}", methodName);` | **关闭** |
| **DEBUG** | 调试信息，详细的业务流程、中间状态 | `log.debug("查询结果: {}", result);` | **关闭** |
| **INFO** | 关键业务流程，重要状态变更 | `log.info("用户登录: userId={}", userId);` | **开启** |
| **WARN** | 警告信息，不影响当前流程但需关注 | `log.warn("缓存未命中: key={}", key);` | **开启** |
| **ERROR** | 错误信息，功能异常，需要处理 | `log.error("数据库连接失败", e);` | **开启** |

### 2.2 级别使用禁忌

**禁止使用场景：**

| 级别 | 禁止行为 | 原因 |
|------|---------|------|
| **ERROR** | 记录可恢复的异常 | 应使用 WARN |
| **DEBUG** | 生产环境开启 | 影响性能、日志量过大 |
| **TRACE** | 生产环境开启 | 敏感信息可能泄露 |
| **INFO** | 记录频繁操作（如循环内） | 日志量过大 |

### 2.3 级别使用场景详解

#### TRACE 级别
- 方法的进入和退出
- 循环内的变量变化
- 详细的调用链追踪
- **仅在开发调试时使用**

#### DEBUG 级别
- SQL语句参数
- 中间计算结果
- 配置信息加载
- 外部API调用参数

#### INFO 级别
- 系统启动/停止
- 用户登录/登出
- 订单创建/支付成功
- 定时任务执行
- 外部系统交互

#### WARN 级别
- 缓存未命中
- 配置项使用默认值
- 资源即将耗尽（如连接池接近上限）
- 重试操作

#### ERROR 级别
- 数据库连接失败
- 外部API调用失败
- 业务异常（如参数校验失败）
- 空指针等运行时异常

## 3. 结构化日志与MDC

### 3.1 MDC（Mapped Diagnostic Context）

MDC用于在整个请求链路中传递上下文信息：

```java
// 在过滤器或拦截器中设置
MDC.put("requestId", UUID.randomUUID().toString());
MDC.put("userId", String.valueOf(userId));
MDC.put("traceId", traceId);

try {
    // 业务逻辑
    log.info("[Service.doSomething] 处理请求");
} finally {
    // 清理MDC
    MDC.clear();
}
```

### 3.2 Logback配置MDC输出

在 `logback-spring.xml` 中配置：

```xml
<pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - traceId=%X{traceId} userId=%X{userId} - %msg%n</pattern>
```

### 3.3 JSON结构化日志

使用 `logstash-logback-encoder` 输出JSON格式：

```xml
<dependency>
    <groupId>net.logstash.logback</groupId>
    <artifactId>logstash-logback-encoder</artifactId>
    <version>7.2</version>
</dependency>
```

```xml
<appender name="JSON_FILE" class="ch.qos.logback.core.FileAppender">
    <file>logs/app.json</file>
    <encoder class="net.logstash.logback.encoder.LogstashEncoder">
        <customFields>{"appName":"my-app","environment":"prod"}</customFields>
    </encoder>
</appender>
```

## 4. 敏感信息脱敏规范

### 4.1 需要脱敏的信息

| 类型 | 示例 | 脱敏方式 |
|------|------|---------|
| **手机号** | 13812345678 | 138****5678 |
| **身份证号** | 1101011990XXXX1234 | 110101********1234 |
| **银行卡号** | 622202XXXXXXXX1234 | 622202******1234 |
| **邮箱** | user@example.com | u***r@example.com |
| **密码** | - | 禁止记录 |

### 4.2 脱敏工具类

```java
public class SensitiveUtils {
    // 手机号脱敏
    public static String maskPhone(String phone) {
        if (phone == null || phone.length() < 11) return phone;
        return phone.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
    }
    
    // 身份证脱敏
    public static String maskIdCard(String idCard) {
        if (idCard == null || idCard.length() < 18) return idCard;
        return idCard.replaceAll("(\\d{6})\\d{8}(\\d{4})", "$1********$2");
    }
    
    // 邮箱脱敏
    public static String maskEmail(String email) {
        if (email == null || !email.contains("@")) return email;
        return email.replaceAll("(.)[^@]*(@.*)", "$1***$2");
    }
}
```

### 4.3 使用示例

```java
// 正确 ✅ - 脱敏后记录
log.info("[UserService.register] 用户注册: phone={}, email={}", 
    SensitiveUtils.maskPhone(phone), 
    SensitiveUtils.maskEmail(email));

// 错误 ❌ - 记录敏感信息
log.info("[UserService.register] 用户注册: phone={}, password={}", phone, password);
```

## 5. 性能优化规范

### 5.1 条件日志判断

对于复杂计算的日志内容，使用条件判断避免不必要的性能开销：

```java
// 正确 ✅
if (log.isDebugEnabled()) {
    log.debug("复杂对象详情: {}", buildComplexDebugInfo());
}

// 错误 ❌ - 即使DEBUG关闭也会执行buildComplexDebugInfo()
log.debug("复杂对象详情: {}", buildComplexDebugInfo());
```

### 5.2 批量操作日志

批量处理时只打印汇总信息，避免循环内日志：

```java
// 正确 ✅
log.info("[BatchProcessor] 开始处理: count={}", orders.size());

int success = 0;
int failed = 0;
for (Order order : orders) {
    try {
        process(order);
        success++;
    } catch (Exception e) {
        failed++;
        // 只记录失败的订单，避免过多日志
        log.warn("[BatchProcessor] 订单处理失败: orderId={}", order.getId());
    }
}

log.info("[BatchProcessor] 处理完成: total={}, success={}, failed={}", 
    orders.size(), success, failed);

// 错误 ❌ - 循环内频繁日志
for (Order order : orders) {
    log.info("[BatchProcessor] 处理订单: orderId={}", order.getId());
    process(order);
}
```

### 5.3 异步日志配置

在 `logback-spring.xml` 中配置异步日志提高性能：

```xml
<appender name="ASYNC_FILE" class="ch.qos.logback.classic.AsyncAppender">
    <queueSize>1024</queueSize>           <!-- 队列大小 -->
    <discardingThreshold>0</discardingThreshold>  <!-- 不丢弃日志 -->
    <includeCallerData>false</includeCallerData>  <!-- 不包含调用者信息 -->
    <appender-ref ref="FILE"/>
</appender>
```

### 5.4 日志文件滚动配置

```xml
<appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>logs/app.log</file>
    <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
        <fileNamePattern>logs/app.%d{yyyy-MM-dd}.%i.log</fileNamePattern>
        <maxFileSize>100MB</maxFileSize>      <!-- 单个文件大小 -->
        <maxHistory>30</maxHistory>         <!-- 保留30天 -->
        <totalSizeCap>1GB</totalSizeCap>       <!-- 总大小限制 -->
        <cleanHistoryOnStart>true</cleanHistoryOnStart>
    </rollingPolicy>
    <encoder>
        <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
    </encoder>
</appender>
```

## 6. 日志配置最佳实践

### 6.1 生产环境配置要点

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <!-- 控制台输出 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 文件输出 -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/app.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>logs/app.%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 异步输出 -->
    <appender name="ASYNC_FILE" class="ch.qos.logback.classic.AsyncAppender">
        <queueSize>1024</queueSize>
        <appender-ref ref="FILE"/>
    </appender>

    <!-- 根日志级别 -->
    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="ASYNC_FILE"/>
    </root>

    <!-- 第三方库日志级别 -->
    <logger name="com.zaxxer.hikari" level="WARN"/>
    <logger name="org.springframework" level="WARN"/>
    <logger name="org.apache.http" level="WARN"/>
</configuration>
```

### 6.2 按环境配置

在Spring Boot中使用profile配置：

```xml
<springProfile name="dev">
    <root level="DEBUG">
        <appender-ref ref="CONSOLE"/>
    </root>
</springProfile>

<springProfile name="prod">
    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="ASYNC_FILE"/>
    </root>
</springProfile>
```

## 7. 日志排查技巧

### 7.1 快速定位问题

```bash
# 查找包含错误的日志
grep -E "ERROR|Exception" app.log

# 按时间范围过滤
grep "2024-01-15 10:30" app.log

# 按请求ID追踪
grep "traceId=abc123" app.log

# 统计错误类型
grep "ERROR" app.log | awk '{print $NF}' | sort | uniq -c
```

### 7.2 常见问题排查

| 问题现象 | 排查方向 |
|---------|---------|
| **日志不输出** | 检查日志级别配置、appender是否正确引用 |
| **日志重复** | 检查是否有重复的appender引用 |
| **性能问题** | 检查是否开启了DEBUG/TRACE、是否使用异步日志 |
| **敏感信息泄露** | 检查日志内容，添加脱敏处理 |
| **日志文件过大** | 配置滚动策略和保留时间 |

### 7.3 日志分析工具

| 工具 | 用途 |
|------|------|
| **grep/awk/sed** | 命令行日志过滤和统计 |
| **ELK Stack** | 日志收集、存储、分析 |
| **Grafana Loki** | 轻量级日志聚合 |
| **Splunk** | 企业级日志分析 |

## 8. 常见问题

### 8.1 性能问题解决
- 使用异步日志配置
- 条件判断避免不必要计算
- 避免循环内打印日志
- 合理设置日志级别

### 8.2 日志级别设置建议

| 环境 | 根级别 | 应用包级别 | 第三方库级别 |
|------|--------|-----------|-------------|
| **开发** | DEBUG | DEBUG | WARN |
| **测试** | INFO | DEBUG | WARN |
| **生产** | INFO | INFO | WARN |

### 8.3 最佳实践总结

1. **日志级别选择**：遵循"INFO用于生产，DEBUG用于开发"原则
2. **日志内容**：包含定位信息、操作描述、关键参数
3. **异常处理**：异常作为最后一个参数，保留完整堆栈
4. **性能优化**：使用异步日志、条件判断、批量汇总
5. **安全合规**：敏感信息必须脱敏处理
6. **结构化输出**：使用MDC和JSON格式便于分析
